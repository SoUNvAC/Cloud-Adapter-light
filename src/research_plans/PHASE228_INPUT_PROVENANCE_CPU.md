# Phase228：六个训练输入的生成来源核验

## 执行范围

只做CPU数据核验，不训练、不运行模型、不使用GPU、不下载或安装依赖，不改写原数据。不读取val/test影像或标签像元，不计算性能。当前任务只核实PNG来源，不做跨头评价。

固定样本见同目录 `phase228_frozen_20261026/SAMPLES.json`：L8、SPARCS各3个不同训练场景，共6张。按场景与文件名排序选取，禁止根据模型表现换样。输入依据与SHA见 `FREEZE_AUDIT.json`。

预算：总计30分钟、内存不超过8GiB、新增交付不超过200MB。缺原件、依赖或达到预算即记录缺口并结束对应项，不追加搜索、补样或重建全量数据。

## 1．准备

1. 核对冻结文件SHA及对应代码SHA，记录Python、NumPy、Pillow、TIFF读取库版本。代码有变化则记录差异，使用冻结版本；无法取得该版本则停止相关核验。
2. 按清单定位当前6张PNG。路径可作工作目录前缀替换，文件名不可替换；保留原路径、实际路径和文件SHA。L8须与冻结image SHA一致，不一致则停止该样本。
3. 仅在已有数据目录／索引内找L8对应的原裁块TIFF、SPARCS已有官方ZIP。不得全盘递归查找、下载、整包解压或覆盖已有文件。原裁块与当前PNG必须有同名映射或生成记录；记录依据。

注意：L8旧物理目录名含test不代表当前test；训练身份以冻结清单的target_train为准。SPARCS训练调度中的 `image_SHA` 是增强后输入SHA，不能当作PNG文件SHA。

## 2．L8：只复现一个固定候选算子

依据 `src/dataset/l8_biome_crop.py` 和 `src/tools/convert_datasets/create_l8.py`，对每个匹配的原裁块TIFF，在内存中复现：

```python
# 前提：原件明确为HWC多波段裁块，波段索引顺序有记录支持。
rgb = np.zeros((image.shape[0], image.shape[1], 3), dtype=np.float32)
rgb[:, :, 0] = image[:, :, 3]  # B4
rgb[:, :, 1] = image[:, :, 2]  # B3
rgb[:, :, 2] = image[:, :, 1]  # B2
rgb = (rgb - rgb.min()) / (rgb.max() - rgb.min() + 1e-6)
candidate = (rgb * 255).astype(np.uint8)
```

- 只读影像，不调用会同时加载标签的Dataset／原导出器，不运行批量导出。
- 一个patch的全部三通道共用min/max；不按通道拉伸、不四舍五入、不加gamma、不搜索其他公式。
- 对当前PNG解码后的RGB数组比较：尺寸、dtype、逐值相等、最大／平均绝对差、任一通道不同的空间像元数、不同通道值数。差值先转有符号类型，避免uint8溢出。
- 原TIFF记录SHA、尺寸、dtype、波段顺序依据及可用格网元数据。没有波段依据时只报告“候选索引算子数值匹配情况”，不得宣称已确认真实B4/B3/B2。
- 原裁块缺失或形状／绑定不明确，记为缺口；不得仅凭文件名x/y从整景自行猜裁块坐标。非有限值或异常布局不自行修补。
- **解码数组完全一致才记EXACT_PIXEL_MATCH**；不同则PIXEL_MISMATCH，保留数值。PNG压缩字节可以因编码版本不同而变化，不以重新编码SHA不同判像元失败。可另报字节比较，但不得混为一项。

## 3．SPARCS：归档成员与当前PNG字节核对

1. 对已有官方 `l8cloudmasks.zip` 流式核对长度与SHA256：
   - 长度：`1555733976` 字节。
   - SHA256：`5cde604615ee241950b5a0b641ae5de82b27738b51e39aa724d18faec0bbaa9a`。
2. 归档身份通过后，仅按3个固定photo文件名定位成员。每个文件必须唯一匹配；流式读取这3个成员、核对CRC并计算SHA，与当前PNG比较。不整包解压，不读取mask／data.tif成员。
3. 成员与当前PNG字节相同记BYTE_MATCH；不同记BYTE_MISMATCH；缺归档／成员或重复匹配如实记录。归档身份失败时不宣称官方来源通过。
4. 官方photo的波段组合、拉伸、gamma只查已有随包说明；找不到写unknown，不尝试由多波段TIFF反推或搜索配方。BYTE_MATCH仅证明发布身份，不证明官方photo的生成方式。
