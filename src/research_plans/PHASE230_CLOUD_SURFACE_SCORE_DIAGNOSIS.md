## 1．怎么跑

1. 核对Source／末头／输入／配置SHA，按229构造插值头；不得改用别的checkpoint或α。
2. 对5模型×10景各前向一次。使用229同一wrapper输出：

   ```python
   z = wrapper(x).float().clamp_min(0)
   p = z / z.sum(1, keepdim=True).clamp_min(1e-12)
   pred = p.argmax(1)
   ```

   父类顺序Surface／Cloud／Shadow。保存归一化后三通道float32分数、映射后的参考标签与ignore支持、scene／模型／输入身份。它们是归一化语义分数，不称为已校准概率或原始分类logits。不对p再做softmax。
3. **每张图**的argmax预测SHA与三类混淆必须精确复现229；不一致停止，不带着漂移分析。检查分数有限、归一化正常，报告零和位置及后续1e-12截断占比；零和有效位置存在时停止相应诊断，不静默删除。
4. 保存分数到单独缓存，单图单模型处理，不一次加载全池；不导出骨干特征。完整50次前向已包含逐图复现，不另跑整池验收；可固定重复排序第一景的5模型，记录最大分数差及预测一致性。

预算：最多 **80次完整输入前向**（含构建探测、重复和失败）、GPU阶段最多 **30分钟**；CPU分析最多60分钟、CPU峰值8GiB、GPU峰值20GiB、新增输出512MiB。50份512×512×3 float32分数约150MiB。超限／缺身份文件就交缺口，不追加前向或换方案。此文档只供执行者运行，本聊天不连接训练机。

## 2．算什么

### 主任务：Cloud vs Surface

仅取有效参考Cloud与Surface；Shadow／ignore排除，参考支持各模型完全相同。固定分数：

```python
d = np.log(np.maximum(p_Cloud, 1e-12)) - np.log(np.maximum(p_Surface, 1e-12))
```

逐景计算：Cloud正类数、Surface负类数、ROC AUC、AP、二类规则d>0的云召回与地表误报，以及两参考类各自d的P10／中位数／P90。d=0按Surface处理，并记录平局数。**实际三类argmax保持229规则**，二类诊断不能替代三类性能。

无正类或负类：AUC／AP保留NA，报告支持，不填0。AP使用完整排序的非插值average precision，ROC AUC平分ties；不得下采样像元、变换支持或用梯形PR面积替代AP。

同时计算全池排序指标、有效场景等权均值；明确各自场景数，不把像元当独立样本，不新算显著性区间。

### 两项辅助任务

- Cloud vs Surface＋Shadow：使用p_Cloud，逐景AUC／AP，检查第三类竞争。
- Shadow vs Surface：使用同样定义的log(p_Shadow)−log(p_Surface)，逐景AUC／AP，核对云影排序是否也变化。Cloud／ignore排除。

三任务分开报告，不以辅助任务替换主任务。

## 4．如何解释与验收

- AUC／AP相近而d整体更偏向Surface、二类漏云增加：支持“主要有决策偏移”的线索；不证明只是一个常数偏置，更不证明校准已修复。
- 同一场景、同一支持下AUC／AP下降：表明不只是均匀分数平移；要报告两seed是否一致，不凭池化结果代替逐景结论。
- 两种现象可并存；区分Cloud/Surface排序与三类竞争，不强行二选一。
- 不按本轮标签寻找最佳阈值／偏置，不加oracle恢复曲线，不训练修复器。此轮只给观测，没有“显著才允许继续”的新门槛。
