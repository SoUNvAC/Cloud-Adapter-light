# Phase103：PixBox标签语义与有效支持锁

## 做什么

仅核验Phase102准入的16产品／10相关组，确定哪些采样点可用于后续云影二分类参考评价。**零训练、零拟合、零预测、零影像下载。**允许读取这些产品的既有标签CSV；不读取13个排除产品的逐点类别。

本轮不作人工判读，不将发布标签称为新核验真值。KappaSet保持pending，不继续扩展。

## 1．读取标签前先冻结映射

依据既有`pixbox_description.txt`和下列规则，先保存映射JSON、代码SHA、16产品／10组清单，再解析逐点类别。先按白名单产品筛选行，不能先统计全部29产品标签。

令C＝CLOUD_CHARACTERISTICS_ID，S＝SHADOW_ID，U＝SURFACE_ID。固定主任务为Shadow vs Surface＋Cloud，不强行构造互斥三类mIoU：

| 条件 | 二分类参考 |
|---|---|
| S=3且C属于{1,7} | 正类：地表云影 |
| S属于{1,2}且C属于{1,7} | 负类：无云影地表，保留地形／树／建筑影作为困难负类 |
| S=1且C属于{2,3,4,5,6,9} | 负类：云，包括透明云与凝结尾迹 |
| 其他组合 | ignore，逐项记原因 |

全局优先排除：字段缺失／未知编码、U属于{9,15,16}的空间云混合、S=4的云上影。C=0不是Clear；S=0不是无影。雾、霾、云边界、空间混合云以及云／地表影冲突不强行归类。

C=1按官方字段“None”解释为该云属性缺席；C=7为显式Clear。两者分别列支持数，不根据数量改映射。若官方说明或已发布CMIX规则与此解释存在实质冲突，先报告语义pending并停止主支持结论，不能现场改映射后继续统计。

映射是本任务的保守支持定义，不宣称完整复刻CMIX评价。原始多属性与排除原因完整保留。

## 2．核验位置与重复支持

1. 核对产品ID、点ID、原坐标、Phase102位置白名单和分组SHA；影像未读取，仍只能验收坐标元数据。
2. 相同产品／相同位置的重复记录：属性一致时合成一个评价位置并保留原ID列表；属性不一致则全部标记冲突ignore，不多数票、不择优。
3. 用原XML格网确定每个采样点所在10m像元及20m像元。坐标约定或像元索引与地理坐标不能唯一调和时记pending，不搜索平移。
4. 列出同一20m单元的采样点数、标签组合及正负冲突。不能把10m点标签自动扩成20m真值，也不在本轮给冲突单元定多数标签；后续输入支持协议须明确处理。

## 3．只报告支持，不评价模型

每产品／每相关组分别列：原始点数、去重数、有效正类、有效地表负类、云负类、地形影负类、ignore各原因、位置pending、20m单元冲突数。列C=1／C=7支持，并报告同一组内的点位聚集程度。

- 给实际可计算采样点AP的组数：至少一个有效正类和一个有效负类；不把“10组”自动称为10个有效云影组。
- 不计算AP、召回或FPR，不载入模型输出，不选择模型、代表或最有利标签子集。
- 不把点数当独立样本量；未知包含概率时，不估计全场景平均／尾部FPR，不声称支持密集分割mIoU。
- 不将这10组分作新校准池。保持为候选外部评价支持；后续是否足够、最低组数与区间宽度，须在模型输出启封前另立协议决定。
