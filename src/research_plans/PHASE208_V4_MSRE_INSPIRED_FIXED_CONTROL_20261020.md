# Phase208：V4冻结底座上的MsRE启发模块与普通残差控制

## 做什么

唯一候选M为Phase207已验收的MsRE-inspired parallel CNN-interface adapter；唯一训练控制B为同位置／同投影的普通残差。一个固定seed、各1000步，只用末步。

评价四策略：原R4、原完整E4、R4+M、R4+B。**不增加适配后集成，不更新原decoder／BN，不加head-delta，不搜索结构／超参数。** C4只引用既有背景。

用户已明确授权执行Phase208固定预算。执行者可在下述实现、输入与资源门通过后，直接按本协议执行，无需再次确认同一授权。不恢复其他分枝，不沿用207的24次工程调用预算。

本轮没有日历日期截止；按下述调用数、GPU运行时长及资源预算执行。


## 1．固定模型和模块

- 底座沿用205／207的V4 R4、N4、HF revision、权重SHA与runtime。原R4／N4全部参数、BN及其他buffer冻结，原模块始终eval；新增模块无BN。不能用整个模型.train()后遗漏将原模块改回eval。
- M原样复用207代码及初始化：最后四级48／104／208／440通道，并行输入／输出投影到384维，核心跨级共享；16tokens、原3／5／7 DW、尺度编码、token计算与scale=1e-3。新增970369参数，不含head-delta。
- 名称保留“MsRE-inspired CNN-interface变体”，不称原DINO MsRE原样跨底座验证；不推论Source强弱因果。

### 普通残差B，只实现这一种

四级位置、输入／输出投影与M相同；共享核心为：

`z = input_projection(feature)`

`d = mean(DW3(z), DW5(z), DW7(z))`

`residual = scale * Conv1x1_384to384(GELU(Conv1x1_384to384(d)))`

`output = feature + output_projection(residual)`

输入投影含bias、输出投影无bias；DW及两层核心1x1均含bias。scale初始1e-3；无tokens、attention、尺度embedding或新norm。B预期944641参数，比M少25728（约2.65%），是近参数量控制，不宣称函数容量严格相同。

仅复制M与B形状／功能相同的输入投影、输出投影及DW参数的初始数值，使共同部分一致；两个网络参数对象必须独立。M其余原初始化不改，B其余两层1x1用固定seed的PyTorch默认初始化。各自保存初始状态；不为让初始预测看起来更好额外置零或调scale。

## 2．训练前实现门

- module/optimizer seed固定20801；两臂初始化与公共部分复制顺序写进代码锁。
- 关闭模块时两臂均精确复现原R4，输出最大差≤1e-5；开启初始化差分别记录，不要求二者开启后完全相同。M初始化非零是207既有性质。
- 使用207同一固定fit裁剪作一次反传验收，无optimizer更新；原网络无梯度、buffer不变，新增路径连通。验证后恢复初始新模块、清梯度，重新初始化优化器及随机数状态，门检不算训练步。
- 实际参数数量与上述预期不符时先查实现；不能加无用参数凑数、改宽度或换第二种控制。
- 图结构、参数／buffer白名单、初始化／复制检查、代码／原权重SHA及输入清单全部封存后训练。

- 原100个fit相关组，严格复用Phase205 seed12201的1000步产品／512裁剪／水平翻转序列，SHA为`3baae5c5e13c3a3dbc515410b537d2071db87e5485953ef87ef5a783b10c0aba`；两臂完全相同。不按标签、旧损伤或模块表现重采样。

## 4．一次固定评价

原Catalogue32组和PixBox16产品／10组，支持与205一致，含全部无影组；不读53校准组，不新加确认池。原R4／E4分数和决策优先复用205同支持缓存。

两新策略只运行单RegNet+模块，原作者20m、1000／300、float32及归一化／后处理不变。一次保存连续Shadow分数、四类argmax及父类预测，不遗漏后补。

固定输出：宏／池化AP、官方四类argmax后合并Cloud的宏召回／误报、最大组误报、零召回组数；Catalogue池化三类mIoU；完整逐组表。PixBox只称采样点指标，不报全景mIoU。

**主要比较M−B宏AP；两个池分别报告，不挑有利池替代另一池。** 同时固定报M−R4、M−E4和B−R4；实际召回、误报、mIoU不得用AP替代。

沿用±1 AP百分点描述改善／稳定／损伤，公开全部组及旧四组。配对相关组bootstrap10000次、seed208020，只作单seed固定模型的描述；7／8个AP组不因像元多变大。区间跨零不是自动停止规则，也不代表等效。

不使用评价侧阈值扫描、oracle预算或重校准，不生成后验回退策略。无影组AP=NA，误报统计完整保留。

## 5．固定小型GPU成本检查

复用119原三产品（33VVE/2017-07-26、22WES/2017-11-07、54TWN/2018-02-22）。每产品按原1000／300坐标顺序选择第一个有image-valid支持的1000窗口，先锁输入坐标／SHA，不按类别选。

对R4、E4、R4+M、R4+B使用同一预归一化输入。每策略／每产品预热1次，计时2次；CUDA事件同步计纯网络段，全部重复留存，运行顺序按产品序号循环轮换，不只取最快。E4计双成员及raw均值运算。构建／预热／失败全部入调用账本。

报告M/E4、M/R4时间比与峰值口径。**只是固定窗口GPU前向，不是完整I/O／拼接／整景速度**；共享进程显存不直接充当各策略独立部署峰值。整景成本未测就写未测，不借用V1的36.4%或参数占比推算实际加速。

## 6．如何判断下一步

- M胜B但不及原R4：最多说明比该新增容量控制少损伤，不构成有用适配增量。
- M胜原R4但不胜B：保留适配收益，MsRE核心的额外价值未清楚显示。
- M相对原R4有收益、对B有增量，且接近／超过E4或有明确成本取舍：才值得讨论另一个seed；不自动追加训练。
- M只胜退化的C4不算通过论据。单seed胜出、局部恢复或某个池化指标胜出都不能宣称稳定替代完整E4。
- M不涨不证明MsRE只能补弱Source短板；即使涨也不证明与Source强弱无关。结论限于这一移植结构、预算和历史暴露支持。
